# Reply gateway

The installer enables the reply gateway by default. It is a delivery safety
net: when a substrate ends a turn without a reply the app took, the gateway
sends user-directed text to the app. A reply counts only when its tool result
is not an error — the app's MCP bridge reports a refused or unreachable app
as `NOT delivered` (an MCP error), and the gateway then sends that reply's
text in front of the turn's text. Claude Code uses a Stop hook;
`shared/scripts/reply-gateway.sh` also has a substrate-neutral poll mode
(`GW_SOURCE=poll`) for substrates without such a hook. UUID, content-hash and
file-lock deduplication prevent duplicate sends.

If `OPENROUTER_API_KEY` is set, Gemma classifies complete turns as `REPLY` or
`NOTE`. API errors and missing keys fail open: delivery wins over silence.

## Automation convention

Prompts generated by cron jobs, rituals or harness automation that must never
be delivered to the user must contain this literal marker:

```
[gateway:silent]
```

Instance-specific literal markers can additionally be placed one per line in
`$EMBERVY_HOME/state/gateway-automation-markers.txt` (`#` starts a comment).
This is an emergency escape hatch; new automation should use
`[gateway:silent]` instead.

Create `$EMBERVY_HOME/state/reply-gateway-off` to disable the gateway. Decisions
are logged to `$EMBERVY_HOME/logs/reply-gateway.jsonl`.

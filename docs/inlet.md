# Inlet graph context

The Claude inlet worker calls `POST /expand` after `/search`, using up to three top search anchors. This adds NEXT/PREV neighbours (including across file-part boundaries) and query-matched SAME_EPISODE context. The existing limit stays at five hits, with 500 characters of text per hit: the strongest three search hits stay first, followed by up to two new contextual hits, then remaining search hits if space permits. When both kinds are available, one contextual slot goes to a neighbour and one to an episode hit. Chunks are deduplicated by filename and chunk index. Search confidence gates are unchanged; unscored neighbours are labelled `context`, not presented as confidence scores. Episode scores are not compared to search scores because the expansion API does not distinguish RRF fallback from reranked scores.

Confirmed `CORRECTED_BY` / `SUPERSEDED_BY` edges produce an English warning directly below the affected hit, with the correcting reference and a short note or snippet. Warnings do not depend on classifier or reranker success. Newly included contextual hits receive a second, veto-only lookup. At most two warnings per hit are shown, each with up to 300 characters of correcting text. **Warnings only appear when confirmed correction edges exist. The product currently has no automatic writer for these correction edges; that arrives in a later update.** Absence of a warning is not evidence that a statement is current.

`INLET_EXPAND=1` is the default (see the root `.env.example`); set `INLET_EXPAND=0` to disable expansion and veto lookups entirely (`off` and `false` also work). Both requests share a one-second deadline, including response-body reads. A missing endpoint (404), invalid response or timeout leaves the original search block available. If only the second lookup fails, the first response's context and warnings remain available. There is no additional model-provider call.

Variety is local and enabled by default (`Claude/scripts/inlet-diversity.ts`): after the confidence gate, the first search pick keeps today's order and each further pick maximises relevance minus 0.5 times its highest word-shingle Jaccard similarity to a selected passage (direct neighbours count as similarity 1). Relevance is the current sort key, including any time boost, min–max normalised to 0–1 over the gated candidates (all equal: 1). After expansion and slot allocation, adjacent chunks in the same file become one excerpt per block, removing the longest exact overlap of at least 20 characters or joining with a blank line. A merged excerpt has the higher score, united sources and all original warnings; its header uses `[Session_1.md#12–13]` and its text budget is 900 characters, while singles stay at 500. Set `INLET_DIVERSITY=0` to restore the original selection and rendering exactly; no extra model call or network request is made.

The worker uses `Claude/scripts/inlet-expand.ts`. Brain benefits automatically when configured to run `Claude/scripts/inlet-worker.ts`: the runtime's environment key is `BRAIN_INLET_WORKER`, and it passes its environment (including `INLET_EXPAND`) to that worker. No Brain changes are required. Brain's built-in retrieval fallback, used when no external worker is configured, is unchanged.

Offline regression tests (local fake RAG server, no external services). Prefix each test path with `./`: without it, Bun treats the argument as a name filter rather than an explicit path.

```sh
bun test ./Claude/scripts/inlet-expand.test.ts
```

## Time channel

Meaning search alone does not know when something was said. When a prompt names a day or a short span, the worker opens a second channel next to it: "what happened yesterday?", "yesterday evening", "last night", "last Tuesday", "the Tuesday before last", "3 days ago" (up to 60), "on September 24", "since 2026-09-20", "last week", "this week", "last weekend". The parser is `Claude/scripts/inlet-temporal.ts` (regular expressions, no model call).

English is built in. The words of another language come from the house's language file, `Claude/app/strings.local.json` (the file that also sets the app's language; no update touches it), in its `"timeWords"` object: weekdays, months, number words, parts of the day, and phrases written as small templates — `"yesterday": ["ayer [{part}]"]`, `"lastWeekday": ["[el] {weekday} pasado"]`, `"daysAgo": ["hace {n} día[s]"]`, date forms such as `"{day}/{monthnum}[/{yy}]"`, and the past and future words, idioms and filler words the rules below use. They are added on top of English. The format is described at `TimeWords` in `inlet-temporal.ts`; `bun Claude/scripts/inlet-temporal.ts --check "a sentence"` lists what the file adds, what was skipped and why, and what the sentence reads as. A broken entry is skipped and logged (`[inlet/time]` on the worker's stderr); the rest keeps working. Brain runs the same worker, so the same file covers both.

- A bare weekday counts only with a past word in the sentence ("what did we discuss on Wednesday?"). Future and idiom forms never count: "tomorrow", "next Tuesday", "in 3 days", "will", "good morning", "how are you today?", "until today". Numbers count as dates only after a date word ("on", "from", "since", or a language file's `datePrefixes`/`sincePrefixes`). System lines (`[gateway…]`, `[Reminder]`, `[system:…]`, `[task]`, `SENSE ·`) are ignored.
- Days end at 04:00 local time in `BRAIN_TIMEZONE`, else `EMBERVY_TIMEZONE` (default UTC): at 00:30 "yesterday" is still the day before the evening you are in.
- The window is read from the session headers' `DATE=` through the rag worker's `GET /files` (sessions of the window with their THEMES/SUMMARY) and `POST /search` with `dateFrom`/`dateTo` (±1 day, because a session around midnight may carry the neighbouring date; the window's own days rank first). The result is a `## Time window (RAG)` block before the chronicle: one line per session (at most six; "evening"/"night" questions show the end of that day first, "morning" questions the start), then up to two chunks from the window, reranked against the rest of the question (one chunk when the prompt asks only about the time). Window chunks under a reranker score of 0.10 are dropped. The meaning search keeps the remaining slots (at least three of five), and a chunk is never shown twice. An empty window gets one honest line ("no archived session") plus the adjacent days; a question about today with nothing archived yet adds nothing, since today is still in the conversation.
- The channel never filters the meaning search: something may have been discussed on another day than it happened. Several references are united; a window over 14 days, or a month ("in September", "last month"), does not open the channel and only ranks meaning hits dated inside it higher (score × 1.25, displayed scores unchanged).
- It runs in parallel with the classifier and the meaning search, with its own 6-second deadline (`INLET_TEMPORAL_TIMEOUT_MS` overrides it), and fails open: a rag worker without `/files` (deployed before this version), an error, a timeout or an unexpected answer adds no time block, and the meaning search runs as without the channel. The one difference left on time turns is a line in the classifier prompt asking it to leave time words out of its queries (without a classifier, the output is byte for byte the same). There is no extra model-provider call.
- Prompts without a time reference produce byte-identical output to the worker without the channel.

`INLET_TEMPORAL=1` is the default; `INLET_TEMPORAL=0` switches the channel off entirely (`off` and `false` also work). `INLET_NOW` (ISO 8601 or epoch milliseconds) fixes "now" for reproducible evaluation runs. Brain passes its environment to the worker, so the same keys apply there. The worker side needs the rag worker of this version (`GET /files`, `dateFrom`/`dateTo` in `/search`, see `shared/rag/README.md`); until it is redeployed, the channel stays silent.

```sh
bun test ./Claude/scripts/inlet-temporal.test.ts ./Claude/scripts/inlet-time-channel.test.ts ./shared/rag/test/rag-worker.test.ts
```
